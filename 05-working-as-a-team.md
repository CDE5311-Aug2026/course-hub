# Working as a team

Think of GitHub like a shared design file with a reviewable history. Your team works in separate branches so one person’s experiment does not overwrite another person’s working screen.

## The simple workflow

1. **Pull before you start.** Bring in the latest shared work before making yours.
2. **Create a branch.** Name it for one task: `add-signup-screen`, not `updates`.
3. **Make and run a small change.** Check it locally.
4. **Commit clearly.** Describe the result: “Add empty-state design to ideas list.”
5. **Open a pull request (PR).** This is the design-review link for code: what changed, why, and how to check it.
6. **Review and merge.** A teammate checks the result before it joins `main`.

## Helpful habits

- One branch and PR per focused task.
- Put the design link, screenshots and test steps in the PR description.
- Keep `main` runnable; do experiments on a branch.
- If another person changed the same area, talk before forcing a merge.
- Pull before every new work session and before opening your PR.

GitHub’s interface changes, so use the current official GitHub docs for the exact buttons. The team habit matters more than memorising the menus.
