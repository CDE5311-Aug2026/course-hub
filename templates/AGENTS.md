# Project instructions for Codex

## Goal

Build a small, usable prototype for the problem described in `brief.md`.

## Before every task

1. Read `brief.md` and `DESIGN.md` before building or changing any screen.
2. Inspect the relevant existing code before proposing changes.
3. Propose a short plan before writing code when a task has more than one step.
4. Work on one focused task at a time; do not broaden the task without asking.

## Build rules

- Follow the design system and screen behaviour in `DESIGN.md`.
- Reuse existing components and project conventions where possible.
- Keep changes small and avoid unrelated refactors or new dependencies.
- Say what is ambiguous, what could break, and how you will verify the result.
- After changes, run the app and report the result.

## Run the app

- Install: [e.g. npm install]
- Start: [e.g. npm run dev]
- Check: [e.g. open the local URL and test the changed screen]
- Test: [e.g. npm test]

## Safety

- Never commit secrets, passwords, API keys, tokens or private user data.
- Do not modify deployment settings, access controls or billing without explicit approval.
- If a task could delete data or overwrite broad changes, stop and ask first.
