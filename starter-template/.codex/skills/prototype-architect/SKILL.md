# Prototype architecture

Read `brief.md`, `DESIGN.md`, `TECH-STACK.md`, and existing project files before planning. Do not write code.

## Create a small plan

1. Name the primary user and their one most important task.
2. Describe the shortest end-to-end user flow.
3. List only the screens and reusable components required for that flow.
4. Identify what can use local fake data and what truly needs saved or shared data.
5. Divide work into: static screen, interactions, then real data.
6. State up to five assumptions or unanswered questions.

Keep the plan to one page. Prefer removing features over introducing backend complexity. End with a checkable definition of done and wait for approval before implementation.
